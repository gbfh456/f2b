# F2B —— 前端 API 配置转后端

针对**火山方舟（ark.cn-beijing.volces.com）等无法被浏览器直连**的接口：把散落在
「插件」和「人物卡」里的前端 API 配置，自动转换成走后端的配置（密钥存服务端、请求由
SillyTavern 服务端转发），并在酒馆页面左上角的悬浮球里统一管理。

> 本仓库**一份代码两个身份**：前端扩展（装到 `public/scripts/extensions/third-party/`）
> 与服务端插件 `f2b-takeover`（装到 `<SillyTavern>/plugins/`）。两边装的是**同一个仓库、同一个 commit**，
> 不会出现前后端版本不一致。安装只需要两条命令/操作，见下一节。

---

## 一、功能

| 功能 | 说明 |
| --- | --- |
| 自动检测（4 类来源） | ① 第三方插件 `extension_settings`；② 当前人物卡数据；③ **浏览器 localStorage**（人物卡脚本常把接口地址/密钥存在这里，例如「手机UI」的 `yinqi-api-chat`）；④ ST 全局变量 / 聊天变量。四处都找“接口地址 + 密钥 + 模型” |
| 没开卡只扫插件 | 停在角色列表页（没点开任何人物卡）时**不扫人物卡数据、也不碰卡片脚本**，这一轮只扫插件 —— 卡片脚本动辄几 MB，没必要在打开之前就跑一遍；点开 / 切换人物卡会自动重扫（`CHAT_CHANGED` 事件） |
| 不扫“卡片脚本宿主” | 酒馆助手（JS-Slash-Runner）的 `tavern_helper` 是卡片脚本的运行时（监听端口 / 脚本仓库 / 变量绑定），里面的地址都是本机端口或卡片脚本自己的东西，**不当作插件 API 配置**（写在忽略表里，就算插件装了也不扫）；`__userscripts`、`regexBinding_scriptId` 同理 |
| 只扫**插件**的设置 | `extension_settings` 里的命名空间必须先确认属于某个**已安装**插件才算数：目录名直接对上、归一化后对上，或查别名表（`baibai_pen` / `baibai_api_channels` 属于 ST-BaiBai-Inkwell、`EjsTemplate` 属于 ST-Prompt-Template）。对不上的（如 `mvu_settings` 这种人物卡脚本写进去的、`YuziPhone` 这种插件已卸载的残留）直接跳过，不进扫描范围，已有的旧条目也会被清掉（不留墓碑，规则变了还能再转回来） |
| 认出“子应用”的存储键 | 插件常把功能拆成子应用、用子应用的名字存 localStorage（Novel-Auto-Generator 的 **txt 转世界书** 存在 `txtToWorldbookSettings`）。f2b 会从**页面已加载过的资源 URL** 学「子目录属于哪个插件」（`…/Novel-Auto-Generator/txtToWorldbook/…`），于是这个键能正确归到「插件 · 小说自动生成器」，并和其它来源的同插件配置并进同一个分组 |
| 凭据兄弟键 | 有的插件把密钥单独存一份（`txtToWorldbookSettings:credentials`），主记录里只剩地址和模型。转成后端时会把兄弟键里的密钥一并取出来写进服务端，否则转过去会没有密钥可用 |
| 存储不留死角 | 既不像已安装插件的设置、当前人物卡脚本里也没出现的存储键，**不静默丢掉**，而是进「疑似前端调用」并写明“来源不明（可能是别的卡或已卸载扩展的残留）”，不会自动转换 |
| 存储按来源分流 | localStorage 里的配置分两类：**插件自己的设置**（键名里含插件目录名/子应用名，如 `txtToWorldbookSettings`）与人物卡无关，**任何时候都扫**，卡片上标「插件存储」、汇总里算进「插件 N」；**卡片脚本用到的键**（形如 `yinqi-api-chat`）只有在**打开那张卡**时才扫，标签写清是哪张卡。别的卡留下的键既不是插件设置、也不在当前卡脚本里，直接跳过 —— 不会再出现「打开一张卡扫出全部」 |
| 只转在用的 | **未启用的插件一律不转换**（配置只是残留数据，它现在不会发请求）；指向 `localhost` / `127.0.0.1` 的配置也不自动转换（浏览器本来就能直连），只在“疑似”里提示 |
| 自动转换 | 检测到的配置会生成一条“后端配置”：地址/模型/密钥写进服务端插件，前端只留地址、模型与密钥指纹 |
| 请求接管 | 命中该配置的 `fetch` / `XMLHttpRequest` 会被改走服务端转发，响应（含流式 SSE）原样回传，插件本身无感 |
| 直连失败兜底 | 静态扫不到的配置（脚本加密、远程下发）也没关系：前端直连报错（CORS/网络）的模型接口会被**自动登记成后端配置并立即转走**，面板里标注为「运行时捕获」 |
| 悬浮球 | 固定在页面左上角，**可拖动**，位置会被记住；点一下展开配置面板 |
| 配置卡片 | 左上角显示**来源**（来自哪个插件 / 哪张人物卡 / 浏览器存储 / 运行时捕获），右上角**删除**（回到前端配置），底部**保存** / **测试连接**，模型栏右侧**拉取模型** |
| 删除即还原 | 删除配置 = 移除服务端条目 + 停止接管该来源的请求，插件恢复自己的前端直连行为；同时记录“墓碑”，不会被再次自动转换 |
| 自动清理 | 插件被停用、配置从浏览器存储里被删掉、或条目指向本机地址时，下一次扫描会自动移除对应配置（不留墓碑，重新启用后还能再转回来） |
| 模型不乱改 | 默认**不会**覆盖插件请求里的 model；只有你在面板里手动改过模型（模型栏出现🔒）才强制覆盖，清空模型再保存即恢复跟随。「测试连接 / 拉取模型」不会把配置标成“手动改过” |
| 手动转换 | 低可信度的“疑似前端调用”（人物卡脚本里挖出来的地址）不自动转换，可在面板里点“转为后端” |
| 三块都能折叠 | 面板分成**已转换 / 疑似前端调用 / 已忽略 · 已恢复前端直连**三块，标题都能点开收起（默认展开「已转换」），折叠状态和滚动位置会被记住 |
| 中文字段名也认 | 国产插件常把配置写成 `api地址` / `密钥` / `模型名称`，这类中文字段名同样能识别（另外 `模型来源`、`模型列表` 这类“看着像模型”的字段会被排除，避免把「自定义」当成模型名）；脚本文本里的 `密钥: "sk-…"` 也算 |
| 同源自动归组 | 同一个插件、同一张人物卡挖出**多条** API 时，会自动折成一个分组（`插件 · txtToWorldbook（2）` / `角色卡 · 银麒赎世（3）`），分组标题右侧也有「全部删除」；只有一条的来源仍直接平铺成卡片，不套多余的框 |
| 一键删除 | 每块标题右侧都有一个批量按钮：已转换 →「**全部删除**」（逐条留墓碑、可再逐条恢复）、疑似 →「**全部忽略**」、已忽略 →「**全部清除**」（只清记录） |

## 二、安装

仓库 root **同时是**前端扩展与服务端插件：`manifest.json` + `frontend.js` + `src/` 由浏览器加载，
`index.mjs` + `proxy.mjs` + `store.mjs` 由酒馆的插件加载器加载（加载器按
`index.js → index.cjs → index.mjs` 探测，所以前端入口改名 `frontend.js`，两份互不打扰）。
两条安装都指向**同一个仓库地址**，装完是同一个 commit。

1. **前端扩展**：酒馆界面「扩展 → 安装扩展」填 `https://github.com/gbfh456/f2b.git`，
   或者手动克隆到 `public/scripts/extensions/third-party/f2b/`：

   ```bash
   git clone https://github.com/gbfh456/f2b.git public/scripts/extensions/third-party/f2b
   ```

2. **服务端插件**：在**酒馆根目录**执行（克隆到 `plugins/f2b/`，不需要手动拷文件）：

   ```bash
   node plugins.js install https://github.com/gbfh456/f2b.git
   ```

   等价于 `git clone https://github.com/gbfh456/f2b.git plugins/f2b`。
   目录名随意：插件 id 由 `index.mjs` 里的 `info.id` 决定，路由恒为 `/api/plugins/f2b-takeover`。

3. 确认 `config.yaml`：

   ```yaml
   enableServerPlugins: true
   enableServerPluginsAutoUpdate: true   # plugins/f2b 是 git 克隆，启动时自动 pull
   ```

4. **重启酒馆进程**（`plugins/` 只在启动时扫描，刷新网页没用），再刷新页面（必要时 Ctrl+F5）。
   控制台出现 `Initializing plugin from .../plugins/f2b/index.mjs`、面板显示「后端已连接 v1.1.0」即成功。

> **为什么服务端那半不能像扩展一样在网页里点一下就装好？**
> 酒馆只为前端扩展开放了远程安装接口（`POST /api/extensions/install`，落点固定是
> `public/scripts/extensions/third-party`），`plugins/` 目录**没有任何 HTTP 写入路径**；
> 服务端插件也不可能在自己尚未被加载时把自己装进去（先有鸡还是先有蛋）。
> 所以这一步必须由你在宿主机跑一条命令 —— 面板检测到后端缺失时会把命令直接摆出来，点「复制命令」即可。

5. 默认需要**管理员账号**：未开启多用户时 ST 的内置用户就是管理员，无需额外设置。
   若开启了多用户，请用管理员登录，否则服务端插件一律返回 403（面板会显示“需要管理员账号”）。

## 三、使用

- 页面**左上角**有悬浮球（顶栏下方，可拖动），徽标数字 = 已转换的配置数量。
- 面板**右上角 ⟳** 是唯一的“重新扫描”入口（底栏不再重复放一个）；面板底栏只保留一行说明文字。
  它的悬停提示会随状态变化：已打开人物卡时是「插件 + 当前打开的人物卡（含这张卡的浏览器存储）」，
  没打开时是「只扫插件（卡片里的配置要打开后再扫）」；点开或切换人物卡后会自动重扫一次。
- **面板可以调大小**：拖右下角斜纹把手改宽高（记住尺寸），**双击把手**恢复默认；窗口变小或换屏幕时自动收进视口。
- **移动面板**：拖标题栏，位置也会记住。
- 删除配置时弹窗底部只有两个等宽按钮「删除并回到前端 / 取消」，会自动换行不挤压。
- 点击悬浮球 → 面板分成三块，标题都能点开收起，标题右侧是**一键删除**按钮：

  | 区块 | 标题右侧按钮 | 作用 |
  | --- | --- | --- |
  | 已转换（N） | **全部删除** | 弹窗确认后删掉所有后端配置、全部回到前端直连；每条都会进到「已忽略」里，可逐条点「重新转换」拿回来 |
  | 疑似前端调用（N） | **全部忽略** | 把所有疑似配置一次性标记为忽略（不转换、不再提示），可在「已忽略」里恢复 |
  | 已忽略 / 已恢复前端直连（N） | **全部清除** | 只清掉这些记录，不动任何配置；下次扫描会重新判定这些来源 |

  点标题右侧的按钮**不会**顺带把这一块折叠/展开。已转换区默认展开，收起后下次打开面板仍是收起的。

- **同一来源的多条配置会自动再折一层**（已转换、疑似两块都这样）：

```
▾ 已转换（5）— 点标题可折叠                        [全部删除]
   ▾ 插件 · txtToWorldbook（2）— 同一来源          [全部删除]
       卡片：来自：插件 · txtToWorldbook
       卡片：来自：插件 · txtToWorldbook（浏览器存储）
   ▾ 角色卡 · 银麒赎世（2）— 同一来源               [全部删除]
       卡片：来自：角色卡 · 银麒赎世（聊天接口）
       卡片：来自：角色卡 · 银麒赎世（绘图接口）
     卡片：来自：插件 · 小说自动生成器        ← 只有一条，不额外套框
```

  归组依据是**来源本身**（插件名 / 人物卡名 / 浏览器存储键 / 运行时主机），
  所以「同一个插件既在设置里存了一份、又在 localStorage 里存了一份」也会并进同一个分组。
  分组默认展开、点标题可收起，展开状态同样会被记住；分组标题右侧的「全部删除」只删这一组，
  同样留墓碑、可逐条「重新转换」恢复。

- 已转换的每张卡片：
  - **左上角**：`来自：插件 · 小说自动生成器` / `角色卡 · 某某`，悬停可看字段路径；
  - **右上角**：启用开关 + 删除按钮（🗑 = 删除并回到前端配置）；
  - **接口地址 / API Key / 模型**：可直接改；Key 留空表示“不修改”，已保存时显示 `ark…3456` 之类的指纹；
  - **模型栏右侧「拉取模型」**：走服务端 `GET {接口地址}/models`，**只把可用的排在前面、已下线的折叠起来**
    （火山方舟的 /models 一次返回 136 个模型，其中 83 个是 `Shutdown`，直接列出来会让人挑到死模型）；
    可用模型点一下即填入，改坏了还能点「恢复：上一次」改回去；列表用可换行的紧凑标签铺开（超过 160 个只铺前 160 个），
    右上角 ✕ 或点面板其他地方即可收起；
  - **底部「保存」/「测试连接」**：保存会把改动写进服务端（密钥只进服务端）；测试会先保存再探测
    `/models`（失败自动回退到接口根地址），并显示 `HTTP 200 · 320 ms · 可用`。
  - **高级**：前端匹配地址、路径重写、认证方式（header / query）、认证头名与前缀、超时、额外请求头。
- **疑似前端调用**（低可信度 / 本机地址 / 停用插件的候选）：每条右侧有「转为后端」和 **🗑 忽略** 两个按钮。
  点 🗑 会记成墓碑：这条不再出现在疑似列表里，也不会被自动转换；想反悔可在面板底部
  「已忽略 / 已恢复前端直连」里点「重新转换」。
- 底部「**已忽略 / 已恢复前端直连**」里的每一条都会写清**来自哪个插件或人物卡**：

  ```
  来自：角色卡 · 银麒赎世   [浏览器存储]
  https://ark.cn-beijing.volces.com/api/coding/v3
  10-19 20:18 · id cfg_8978bfe1          [重新转换] [🗑]
  ```

  来源名、地址、类型、时间在删除/忽略的那一刻一起存进 `settings.tombstoneInfo[cfgId]`；
  旧版本留下的“只有 id”的墓碑，会在下次扫描时自动补上来源（对不上就显示「来源未知（原始配置已不存在）」）。

  每条右边有两个按钮，作用不同：

  | 按钮 | 作用 |
  | --- | --- |
  | 「重新转换」 | 取消忽略 **并立刻重新扫描**：该来源重新判定，能转成后端的就直接变成上面的配置卡片 |
  | 🗑 删除 | 只把这条**记录**删掉（不再保留忽略标记），不触发扫描；该来源会在**下一次扫描**时像新配置一样重新判定 |
- 删除配置时的确认弹窗会列出**来源 / 接口 / 模型**三行，并说明“恢复前端直连 + 服务端密钥一并删除 + 以后不再自动转换”。
- 面板会**记住折叠状态和滚动位置**：收起「已转换」、展开「已忽略」或某张卡片的「高级」后再删除/保存，
  列表不会自己折叠回去、也不会跳回顶部。
- 面板顶部是汇总（只列有值的来源）：`已转换 N 项 · 插件 x · 角色卡 y · 存储 z · 疑似 v`，一眼看出配置从哪来；
  这一行**不会被裁切**，窄屏时整行换行显示，悬停可看全文。
- 「扩展设置」里的抽屉（默认收起，点标题展开，跟其他插件一样）：显示/隐藏悬浮球、开关请求转发、开关自动转换、
  探测插件是否真的从前端调用、**前端直连失败时自动改走后端**（默认开，关闭后只登记不自动转），
  下面两个按钮是 **[配置面板] [重新扫描]**：按文字宽度自然宽、左对齐、间距 6px，只去掉酒馆 `.menu_button` 的 `width:min-content` 和 `margin:5px 0`（否则一大一小、上下错位），字号和内距仍沿用酒馆默认。

## 四、转换是怎么生效的

```
插件/人物卡  →  fetch('https://ark.cn-beijing.volces.com/api/v3/chat/completions', {…})
                     │  ← 命中已转换配置（同源 + 路径前缀，或密钥指纹）
                     ▼
        POST /api/plugins/f2b-takeover/proxy   { url, method, headers, body(base64), cfgId }
                     │  ← 服务端补上密钥 / 覆盖 model / 套用 baseUrl，流式转发
                     ▼
        https://ark.cn-beijing.volces.com/api/v3/chat/completions
```

- 只接管**命中配置**的请求；酒馆本体与其他插件的请求一律原样放行。
- 酒馆自己的 `/api/*` 后端接口永不接管（避免递归）。
- 前端不保存明文密钥；服务端条目里只返回 `hasKey` / `keyPreview`。
- 未在面板里填 Key 时，服务端会**透传插件自己带的认证头**，所以“只解决跨域”的场景可以先不填 Key。

## 五、外观

悬浮球与面板都是**半透明玻璃态**（背后聊天内容可见）：

| 想改什么 | 去哪里改 |
| --- | --- |
| 面板透明度 | `style.css` 里 `.f2b-panel` 的 `--f2b-glass`（默认 `rgba(14,17,24,0.72)`，把 0.72 改小更透、改大更实） |
| 标题栏 / 底栏透明度 | 同上的 `--f2b-glass-strong` |
| 面板默认宽度 | `width: clamp(340px, 34vw, 500px)`（拖右下角把手可以手动改，改过之后用记住的尺寸） |
| 面板最小尺寸 | `.f2b-panel` 的 `min-width: 320px` / `min-height: 220px` |
| 缩放把手样式 | `.f2b-foot-grip`（右下角斜纹，hover 变亮） |
| 扩展设置里的抽屉 | 酒馆原生三件套 `inline-drawer` + `.inline-drawer-toggle.inline-drawer-header` + `.inline-drawer-content`：**默认收起**（ST 的 `.inline-drawer-content{display:none}`），点标题展开、箭头跟着翻；标题栏底色/圆角由 ST 的 `#extensions_settings2` 规则负责，行距用 `.flex-container`（gap 5px），f2b 不额外加 margin 或字号覆盖，所以跟其他插件一模一样 |
| 标签列宽 | `--f2b-label-w`（默认 74px） |

排版规则：每一行都是 `[标签 | 内容]` 的 grid，内容列 `minmax(0, 1fr)` + `min-width: 0`，
长地址 / 长模型名一律省略号，不会被撑宽或挤出卡片；「额外请求头」等宽字段自动换成上下两行。

## 六、常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 人物卡里的「小手机 / 手机UI」这类脚本用了 API，但面板里没有 | 这类脚本把配置存在浏览器 `localStorage` 里。本扩展会扫 localStorage；若仍然没有，直接触发一次它的生成——直连失败会被自动登记成「运行时捕获」配置 |
| 某个插件明明配了 API 却不在面板里 | 该插件在「扩展」列表里是停用状态（停用的插件不转换），或地址是本机地址（只在“疑似”里提示） |
| 面板显示「未检测到后端插件 f2b-takeover」 | 后端那半还没装：在酒馆根目录跑 `node plugins.js install https://github.com/gbfh456/f2b.git`（面板里点「复制命令」即可）。已装过仍报错，则是没放在 `plugins/` 下、`enableServerPlugins: false`，或没重启酒馆进程 |
| 安装提示里点「复制命令」没反应 | 非 https 页面上 `navigator.clipboard` 可能不可用，代码会退化成 `execCommand`；都失败时按提示手动复制（命令就是上一行那句） |
| `plugins/` 里同时有 `f2b` 和旧的 `f2b-takeover` | 两个目录声明了同一个插件 id，后加载的那个会报 `plugin ID is already in use`。删掉旧目录，只留 `plugins/f2b` |
| 显示「需要管理员账号」 | 多用户模式下用了普通账号登录，改用管理员账号 |
| 测试连接 401 / 403 | Key 不对或没填；填好 Key 点保存再测 |
| 转换后插件仍报 CORS | 该请求没命中配置：检查卡片「高级 → 前端匹配」是否覆盖了插件实际请求的地址 |
| 转换后插件报 404 | 接口地址多了/少了版本段：测试连接会显示实际请求地址，按提示改「接口地址」 |
| 不想让它再自动转换 | 删除配置（会留下墓碑），或关掉「自动转换为后端」 |
| 拉取模型为空 | 部分服务不提供 `/models`；直接手填模型名即可 |

### 面板里为什么不再出现 `mvu_settings` 这类条目

因为那不是插件的配置。`mvu_settings` 是 **MVU 变量更新框架**的设置（里面是“额外模型解析配置 / 自动清理变量 / 通知”这些），
而 MVU 是随**世界书 / 人物卡**分发的脚本（本机只出现在世界书 `【TG】天书江湖录.json` 里），它通过酒馆助手把自己写进
`extension_settings.mvu_settings` —— 装了哪个插件都不会用它，所以不扫。

判断规则：命名空间必须能对上某个**已安装**插件（目录名 / 归一化名 / 别名表），ST 自带模块另算。
对不上的一律跳过，控制台会打印一行 `[f2b] 以下设置项不属于已安装插件，已跳过：…` 方便排查。
`YuziPhone`、`TamakoMarket`、`xianshilouceng` 这些同理：对应插件没装，只剩残留。

如果某个插件确实是装的、却没被扫到，把它的**目录名**和**设置命名空间**告诉我，加到别名表里即可。
### 插件的 API 扫不出来怎么办

1. 先确认这个插件**是启用状态**——停用的插件按设计不转换（面板汇总里不会计入）。
2. 面板汇总里看 `插件 N`：为 0 说明 `extension_settings` 里没有可识别的地址。
3. 新版已支持中文字段名（`api地址` / `密钥` / `模型名称`），也会从**已加载资源**里认出子应用名对应的插件
   （例：`Novel-Auto-Generator` 的 txt 转世界书用 `txtToWorldbookSettings` 存设置，会被归到「插件 · 小说自动生成器」，
   密钥从 `txtToWorldbookSettings:credentials` 自动补齐）。这类配置要等插件**加载完**才认得出，
   所以扩展全部加载完（`APP_READY`）后 f2b 会自动再扫一次，也可以用右上角 ⟳ 手动补扫。如果还是没有，多半是插件把地址写在了
   **非 JSON 字段**里（例如整段字符串、或运行时才拼出来）——这种走「直连失败兜底」：
   该插件真发请求并失败时（CORS / 网络错误），f2b 会自动把它登记成后端配置，面板里标「运行时捕获」。
4. 存储里来源不明的配置会出现在「疑似前端调用」里，点「转为后端」即可手动接管。
| 拉取模型里挑了一个，结果生成报错 | 挑到的是服务端标为 `Shutdown/Retiring` 的模型。新版已下线的会折叠标注，可用模型排在最前；改错了点「恢复：上一次」再保存即可 |
| 想彻底停用 | 抽屉里关掉「启用请求转发」或禁用本扩展 |

## 七、安全说明

- 密钥只存在 `<数据目录>/<用户>/f2b-takeover/secrets.json`，任何接口都不返回明文。
- 前端设置里只有 `cfgId`、来源、地址、模型、密钥首尾指纹与匹配规则。
- 删除配置会同时删除服务端的配置与密钥。
- 请求日志只记录时间/状态码/耗时/URL（敏感查询参数打码），不含请求体、响应体与请求头。

## 八、卡片内界面（小手机）为什么必须额外接管 iframe

「银麒赎世」这类人物卡的小手机界面**不是直接跑在酒馆页面里，而是跑在同源 iframe（blob:/srcdoc）里**。
顶层 `window.fetch` 的补丁管不到 iframe 自己的 `fetch`，所以它们的请求会继续走浏览器直连，
被 CORS 拦掉 —— 表现就是「获取模型失败」「生成失败」，而后端日志里一条记录都没有。

因此扩展会：

1. 递归接管页面里所有同源 iframe（含嵌套帧）的 `fetch` / `XMLHttpRequest`；
2. 用 MutationObserver 盯住后新建的帧，并在帧 load 后补接管（blob:/srcdoc 文档是异步解析的）；
3. 每 4 秒补扫一次（已接管的窗口/帧会跳过，开销可忽略）。

### 小手机的 /v1 问题

小手机拼地址的规则是 `base + "/v1/" + path`（脚本里写死的），而火山方舟的真实路径**没有 /v1**：

| 请求地址 | 结果 |
| --- | --- |
| `https://ark.cn-beijing.volces.com/api/coding/v3/models` | 200 |
| `https://ark.cn-beijing.volces.com/api/coding/v3/v1/models` | **404** |
| `.../api/coding/v3/chat/completions` | 200 |
| `.../api/coding/v3/v1/chat/completions` | **404** |

所以转发层会自动纠偏：先按原样发；上游回 404/405 且路径是模型接口形态、且含 `/v1/` 时，
把 `/v1` 去掉再发一次，成功就记住这个组合（下次直接按修正后的路径发，只多一次 404 的开销）。
修正只对 `/models` `/chat/completions` `/completions` `/embeddings` `/messages` `/responses` `/rerank` 这几类路径生效，其它 404 原样返回。

### 为什么第一次拉取模型后地址会多出一层 /v1

第一次拉模型时，小手机的请求是 `…/api/coding/v3/v1/models`。如果这次请求是**浏览器直连失败后被兜底接住**的
（iframe 还没被接管、或该接口当时还没登记），扩展会按请求地址反推基础地址 —— 而反推规则会把那一层 `/v1` 一起带进来，
于是面板里就出现了 `…/api/coding/v3/v1`。

现在做了三层处理，这种地址不会再出现：

1. `apiBaseOf()` 反推基础地址时，如果**相邻两段都是版本号**（`…/v3/v1`、`…/v1/v1`），自动丢掉后面那段；
2. 所有条目写入（扫描导入、运行时捕获、服务端遗留导入、手动保存）都过一遍 `dedupeApiBase()`，`接口地址` 和 `前端地址` 都不会再带多余版本段；
3. 已经存进设置/服务端的旧地址会自愈：启动时的规整会改内存值并落盘，扫描对账时发现服务端 `baseUrl` 与本机不一致就回写一次。

> 正常的单层版本地址不受影响：`https://api.openai.com/v1`、`https://host/custom/api/v1` 都保持原样。

## 九、配置都在哪里

| 来源 | 位置 | 面板标签 |
| --- | --- | --- |
| 第三方插件 | `extension_settings.<命名空间>` | `插件 · 名称` |
| 人物卡 | `characters[i].data.extensions` | `角色卡 · 名称` |
| 插件存储 | `localStorage` 里键名能认出扩展的项（如 `txtToWorldbookSettings`） | `插件 · 名称（浏览器存储）` + 徽标「插件存储」 |
| 人物卡存储 | `localStorage` 里键名出现在**当前这张卡**脚本中的项（如 `yinqi-api-chat`） | `角色卡 · 名称` + 徽标「浏览器存储」 |
| 酒馆变量 | `extension_settings.variables.global`、`chat_metadata.variables` | `变量 · 全局变量 / 聊天变量` |
| 运行时捕获 | 由失败请求反推的接口前缀 | `运行时捕获 · 主机名` |
| 服务端遗留 | `f2b-takeover/config.json` | `服务端 · 遗留配置` |

> 转换不会改写插件/脚本自己的配置（也不会删掉前端那份密钥）：只是把请求改走后端，
> 所以随时删掉配置就能 100% 回到原来的前端直连行为。

## 十一、卸载

**面板里就有入口**：悬浮球面板底部那枚「卸载」，或「扩展设置 → F2B 前端 API 转后端 → 卸载说明」，
点开就是完整命令 + 一键复制。命令行侧**不需要任何参数**：

```bash
node public/scripts/extensions/third-party/f2b/uninstall.mjs
```

它会先打印「将要处理」的清单，再问一次 `y/N`，答 `y` 才动手（不打参数、不记得任何开关也能用）。
其它模式按需：

```bash
node .../uninstall.mjs --dry-run     # 只列清单，不删
node .../uninstall.mjs --keep-keys   # 保留 data/<用户>/f2b-takeover/ 里已存的密钥
node .../uninstall.mjs --yes         # 免确认（也可 echo y | node .../uninstall.mjs）
node .../uninstall.mjs --force       # 酒馆还开着也照删（不推荐）
```

会清掉：`plugins/<目录>`（按 `info.id` 认，不写死目录名）、前端扩展目录（含 `.git`）、
`data/<用户>/f2b-takeover/`（配置 + 明文密钥）、`data/<用户>/settings.json` 里的
`extension_settings.f2b` 与停用列表里的 `third-party/f2b`（改前留 `.bak`）。

两件脚本管不了的事：**正在运行的进程里已加载的路由要重启才消失**（所以脚本发现端口在监听会拒绝执行）；
`data/<用户>/backups/` 里的历史 settings 快照可能仍含 f2b 的配置项（但不含密钥文件）。
浏览器侧没有残留：f2b 只读 `localStorage`，不往里写任何东西。
